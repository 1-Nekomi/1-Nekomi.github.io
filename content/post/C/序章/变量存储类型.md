# 变量存储类型

​	变量和函数有两个属性：数据类型和数据存储类型。其中数据存储类型可分为四种：

①自动地（auto）

②静态的（static）

③寄存器的（register）

④外部的（extern）

​	上述四种存储类型可以概括为**静态存储方式**和**动态存储方式**，内存中供用户使用的存储空间如下：

|     程序区     |
| :------------: |
| **静态存储区** |
| **动态存储区** |

根据不同数据所声明的存储类型放入不同的区块。

在详细介绍这四种数据存储类型前，需要先了解变量的**作用域**和**生存期**的概念：

## 序章 作用域和生存期

​	作用域是指**一个变量如果在某个或某些文件、函数范围内是有效的**，则将该范围称为“作用域”。在此作用域内能够对变量进行引用，则说明该变量具有“**可见性**”。生存期是指**一个变量值在某一个时刻时是存在的**，其存在的时间总和即为变量的“生存期”，例如：

```c
int a;
void function1(){
    int b;
    ...
}
void function2(){
    int c;
    ...
}
```

变量a的作用范围是整个文件，生存期是程序运行期间；变量b的作用范围是function1函数，生存期是function1函数执行期间；变量c作用范围是function2函数，生存期是function2函数执行期间。



接下来详细介绍变量的四种存储类型：

## 1. auto变量

​	对于形式参数、局部变量而言，其在对应函数被执行完成后其所占用的存储空间便会被释放。在这个过程中是完全自动的，例如：

````c
int function(int a,int b){
    auto int c = 10;
    ...
}
````

​	对于形式参数a，b以及局部变量c而言，当function函数被执行完后其所占用的存储空间便会被释放。不像**全局变量会在程序运行期间一直占用存储空间直到程序执行完成**。

​	其实“auto”关键字可以省略，若其不写则隐含为“自动存储类别”，其属于动态存储类型。程序中大多数变量都属于auto变量。

## 2. static变量

​	其用于**在函数调用结束后保留局部变量的值**，即被static声明的局部变量在函数调用完成后其占用的存储单元不释放，在下一次该函数进行第二次调用时，该函数就已经存有值。该函数被称为“静态局部变量”。例如：

```c
int function(){
    auto int a = 3;
    static int b = 4;
    a++;b++;
    return (a+b);
}
```

​	对于上述函数，执行第一次的结果为9，第二次结果为10。我们接下来详细分析：

​	当第一次被调用时，a的存储类型为auto，因此无论调用几次，在调用时都会被初始化为3，经过一次累加，则为4，对a累加是无意义的，因为a只能永远为4。而对于b而言，其被static关键字修饰，作为静态局部变量进行存储，因此无论调用几次，b都会**继承上一次调用该函数的结果作为这次调用的初始值**，因此累加操作是有意义的，每次调用能使b值加1。

​	静态局部变量属于**静态存储类型**，在静态存储区内分配存储单元，程序运行的整个过程都不会释放。对于其的初始化也**只会进行一次**，对其进行的初始化是在编译时进行的。若不对其进行初始化，则会自动赋值为0或者空字符（'\0'）。

​	注意：静态局部变量无法被其他函数引用。

​	与此同时，static关键字也可以用来**限制变量的作用域**。例如：

```c
static int a;
void main(){
    ...
}//文件1
```

当在声明全局变量为static类型时，其他文件无法通过extern（详见本章第4节）来拓展变量的作用域。例如：

```c
extern int a;
void function(){
	...
}//文件2
```

其中试图通过extern来将文件1中的a变量作用域拓展到本文件，但由于a的声明为static类型，因此该语句是无效的，文件2也就无法使用变量a了。

​	这样可以有效提高函数的单一性和通用性，不至于函数与函数之间矛盾。



*拓展内容*：

​	这部分不涉及变量存储类型，但关系到static的另一种用法。即函数作用域。很明显，函数一样和变量拥有作用域（生存期就是其调用时长），这里原理和变量作用域类似，不再赘述。

​	使用static声明函数，能让函数的作用域只限于本文件内，其他文件无法对该函数进行调用操作。例如：

```c
static int function();
```

这种函数被称为“**内部函数**”。

## 3. register变量

​	对于某些**值改变次数比较频繁**的变量，如果使用控制器→内存→运算器→控制器→内存（即控制器发出指令从内存中取出变量的值传送给运算器，运算出值后再由控制器存入内存）的方式，那么消耗的时间则会大幅增加，例如：

```c
int function(){
    auto int num = 0;
    int i;
    for(i=0;i<100000;i++)
        num++;
}
```

如果使用auto，则会让变量取出内存再存入内存的次数达到100000 x 2次，假设存入和取出的时间均为1 μs，那么完成此次运算则需要200000 μs，也就是200 ms，大幅增加了运算时间。

​	假设我们在num的定义前加上register声明，那么在num参与运算的时候，系统会将局部变量的值放到CPU的寄存器中，运算时直接从CPU的寄存器中取出参与运算。注意从寄存器中取出变量的速度远大于从内存中取出变量的速度。声明形式一般如下：

```c
register int num = 0;
```

​	由上述例子不难看出，合理利用register声明可以提高执行效率，但是**寄存器空间一般小于内存，不能过多地设置寄存器变量**，同时还有以下注意事项：

①只有局部变量和形式参数可以被设置为寄存器变量；

②局部静态变量不能设置为寄存器变量，意思是static关键字和register关键字无法共存；

​	但是一般来说，如今的大多数编译系统都能识别出使用频繁的变量并将其自动设置为寄存器变量，因此可以不学习利用register来声明变量。

## 4. extern变量

​	外部变量是**在函数外部定义的全局变量**，其作用域是从变量的定义处开始，到本文件结尾。用extern声明外部变量能够**拓展变量的作用域**。拓展类型分为**文件内**和**文件外**。

​	对于文件内作用域拓展，如果外部变量定义并不在文件开头，而变量定义语句前的函数若想要使用该变量的话就要在需要使用变量的函数内进行extern声明。例如：

```c
void main(){
    extern a;
    printf("%d",function(a));
}
int a = 10;
int function(int a){
    ...
}//文件1
```

由于c的编译是逐句进行，若在定义变量a语句前的函数想要使用变量a，则需要告诉编译系统该变量存在定义，不难看出，extern的作用就是如此。但是不能只有extern而没有定义，否则按报错处理。

​	对于文件外作用域拓展，如果另一个文件想要使用上述定义的外部变量a，那又怎么办呢。同样可以使用extern关键字将变量a的作用域拓展到另一个文件。例如：

```c
extern a;
void FUNCTION(){
    a++;
    ...
}//文件2
```

这样一来就能将文件1中的外部变量a的作用域拓展到文件2中，供文件2中的函数使用。

关于extern声明：在对变量进行extern声明时可以忽略变量的类型，意思如下：

```c
extern (int) a;
```

对于变量的类型，可以忽略，也可以写。

​	这样一来就能将变量的作用域拓展到其他函数和其他文件中去。



*拓展内容*：

​	使用extern可以拓展函数的作用域，供其他文件进行调用。例如：

```c
extern int function();
```

这种函数被称为“**外部函数**”。

​	接下来举出实例供读者参考：

```c
#include<stdio.h>

void main(){
    extern int add(int,int);
    extern int reduce(int,int);
    extern void print(int,int);
    
    int a,b,c,d;
    scanf("%d %d",&a,&b);
 
    c = add(a,b);
    d = reduce(a,b);
    print(c,d);
}//文件1
```

```c
#include<stdio.h>

int add(int a,int b){
    return a+b;
}//文件2
```

```c
#include<stdio.h>

int reduce(int a,int b){
	return a-b;
}//文件3
```

```c
#include<stdio.h>

void print(int c,int d){
    printf("c = %d,d = %d",c,d);
}//文件3
```

​	static限制函数作用域方法同理，请读者自行实验。上述代码可以使用任意一个编译器去尝试运行它。而且笔者实验时也发现如果在文件1中尝试由声明跳转定义，编译器可能会提示找不到实现，但程序却可以正常运行，这也许是一种能够隐藏实现文件的简单思路（但用户可以通过翻找项目文件夹来找到实现）。



## 结语 存储类型总结

​	首先判断各个变量的作用域和存在性：

| 变量类型 | 函数内作用域 | 函数内存在性 | 函数外作用域 | 函数外存在性 |
| :------: | :----------: | :----------: | :----------: | :----------: |
|   auto   |      √       |      √       |      ×       |      ×       |
|  static  |      √       |      √       |      ×       |      √       |
| register |      √       |      √       |      √       |      ×       |
|  extern  |      √       |      √       |      √       |      √       |

其次根据**作用域**角度进行详细划分：

|                 局部变量                 |                    全局变量                    |
| :--------------------------------------: | :--------------------------------------------: |
|      动态局部变量，离开函数值就消失      |          静态外部变量，只限本文件引用          |
|      静态局部变量，离开函数值仍保留      | 外部变量（非静态的外部变量，允许其他文件引用） |
|       寄存器变量，离开函数值就消失       |                       ——                       |
| 形式参数（可以视为自动变量或寄存器变量） |                       ——                       |

然后是根据**生存期**角度进行详细划分

|         动态存储         |               静态存储               |
| :----------------------: | :----------------------------------: |
|  自动变量，本函数内有效  |      静态局部变量，本函数内有效      |
| 寄存器变量，本函数内有效 |      静态外部变量，本文件内有效      |
|  形式参数，本函数内有效  | 外部变量，本文件有效且其他文件可引用 |

最后是根据**变量存放位置**来区分

| 内存静态存储区 | 内存动态存储区 | CPU中的寄存器 |
| :------------: | :------------: | :-----------: |
|  静态局部变量  |    自动变量    |  寄存器变量   |
|  静态外部变量  |    形式参数    |      ——       |
|    外部变量    |       ——       |      ——       |
