# 常用的Linux命令技巧

在Linux bash上进行部分操作的时候，总是会遇到一些很麻烦的情况，例如我想往上找我曾经执行的命令，假设这个命令是在我十几分钟前执行的，那么我有可能要连续按上箭头好几分钟才能找到，甚至不注意还有可能看漏掉。后面才知道Linux bash面对大部分情况其实都有相关的技巧可以解决这些问题，为了防止遗忘，这篇文章专门用于记录这些命令技巧。仅用作个人学习用途，因此不会列出所有相关技巧。

## 反向搜索模式

还是引言的那个问题，假设我想要找到一个我曾经执行过的命令，但这个命令又不是我最近才执行的，那么此时可以通过 <kbd>CTRL</kbd> + <kbd>R</kbd> 快捷键进入Linux bash的反向搜索模式，以Ubuntu 22.04LTS-WSL为例，按下快捷键后命令提示行会变成：
~~~bash
(reverse-i-search)`':
~~~

说明此时进入了 **反向搜索模式** ，此前我已经执行了如下命令：

~~~bash
cd ~
docker images ls
touch dockerfile
vim dockerfile # 任意编辑内容
docker build -t myapp .
rm dockerfile
docker images ls
~~~

此时我们进入反向搜索模式，键入`docker`，会出现：
~~~bash
(reverse-i-search)`docker': docker images ls
~~~

此时会显示出最早能够匹配的命令，如果我们想要的不是这个，那么再次按下 <kbd>CTRL</kbd> + <kbd>R</kbd> 快捷键可以跳到下一个存在关键字匹配的命令。

确定好命令后，按下 <kbd>ENTER</kbd> 可以直接执行指定命令，按下 <kbd>→</kbd> 可以将该命令放置于命令行上。

## 命令权限拒绝

有时候我们需要以root身份来进行某些操作，例如想要执行下面的新建文件命令就需要root身份：
~~~bash
touch /etc/testfile.txt
~~~

但我们在执行这个命令的时候忘记加上了`sudo`来提权，因此会出现`Permission denied`权限不足的问题。

这个时候我们一般会按下 <kbd>↑</kbd> 键来获取刚才因权限不足被拒绝执行的命令，然后在开头加上`sudo`后再次执行，但不需要这么麻烦，实际上执行以下命令直接等效上述的操作：
~~~bash
sudo !!
~~~

其中`!!`表示你执行的上一条命令，执行这个命令后，bash会输出补全后的完整命令，以上面为例：
~~~bash
$ sudo !!
sudo touch /etc/testfile.txt
~~~

## 复用最新参数

假设我们刚才执行了命令：
~~~bash
ls /usr/local/share/man/
~~~

然后我们想在该目录下新建一个文件，也就是执行命令：
~~~bash
touch /usr/local/share/man/test.txt
~~~

可以发现我们还要再打一遍我们刚刚已经输入过的长路径参数，其实不需要这么麻烦，只需要在输入了操作`touch`后，按下 <kbd>Alt</kbd> + <kbd>.</kbd> 快捷键会自动帮我们补全上一个命令所使用的 **最后一个参数** ，再按一次会往前循环更早命令的最后一个参数。

## 文件夹回溯

假设我们此时需要管理两个文件夹`/usr/local/share/SourceCode`和`/opt/lib/TestHelper`，如果我们经常需要在两个文件夹之间反复横跳，一个方法是开两个bash进程；另一个方法是使用命令：

~~~bash
cd -
~~~

这个命令会将工作目录设置到上一个你还在的目录。如果经常需要返回上下层级目录，除了`cd ..`也可以使用这个命令，且速度更快，因为你不需要输入下层级目录的名字。

## 命令行跳转头尾、删除前一词

输入快捷键 <kbd>CTRL</kbd> + <kbd>A</kbd> 可以跳到命令行头；

输入快捷键 <kbd>CTRL</kbd> + <kbd>E</kbd> 可以跳到命令行尾；

输入快捷键 <kbd>CTRL</kbd> + <kbd>W</kbd> 或者 <kbd>Alt</kbd> + <kbd>DELETE</kbd>可以删除前一词。

## sudo错位

假设我们想要执行以下命令：
~~~bash
sudo echo "Hello World" >> /etc/.testfile
~~~

上述命令的最终结果是`Permission denied`。奇怪，我们不是用了`sudo`进行提权吗，为什么还是权限不足？这是因为`echo`这个操作本身不需要root权限，但如果想要写入`/etc/.testfile`就需要root权限，而`sudo`并没有正确对应后面写入文件的命令。正确的做法是新增管道，然后用root身份下的`tee`写入文件：

~~~bash
echo "Hello World" | sudo tee -a /etc/.testfile
~~~

此时就能正确写入内容（`-a`选项是在指定文件后追加内容，若不指定该选项会覆盖源文件的内容）。

> [!tip]
>
> `tee` 的核心作用是**分流输出**。它从标准输入读取数据后，会同时完成两件事：一份送到**标准输出**（通常是你的屏幕或下一个管道命令），另一份写入一个或多个**指定文件**。
>
> 相关常见参数请自行检索或者使用`--help`选项获取系统帮助。

## 大括号拓展

若我们执行以下命令：
~~~bash
echo {1...5} # 输出1到5
echo {a...e} # 输出a到e
echo {1...100...10} #输出1到100，每次步长为10
~~~

上述运行结果如下：
~~~txt
1 2 3 4 5
a b c d e
1 11 21 31 41 51 61 71 81 91
~~~

因此，我们可以利用这个特性来批量创建文件：
~~~bash
touch file{1...5}.txt # 创建file1、2、3、4、5的txt文件
~~~

或者批量删除指定格式的文件：
~~~bash
rm *.{pdf,jpg,jpeg,png}
~~~

## 命令暂存

如果输入某个命令输入到一半，发现我们需要先暂时保存这个命令，可能是因为我们需要先跑其他程序，亦或者我们忘记了某一个参数名字，这个时候可以使用快捷键来暂存和恢复已经写好的命令

输入快捷键 <kbd>CTRL</kbd> + <kbd>U</kbd> 可以暂存命令；

输入快捷键 <kbd>CTRL</kbd> + <kbd>Y</kbd> 可以恢复命令。

## 作业暂停和后台执行

假设我们正在使用包管理器进行`update`操作，而这个时候我们需要释放终端来执行另一个作业，可以使用<kbd>CTRL</kbd> + <kbd>C</kbd>来直接杀死当前作业，但这样后续想要恢复就需要重新执行命令，就比较麻烦。

但我们也可以作业程序或者让作业后台执行，只需要按下快捷键<kbd>CTRL</kbd> + <kbd>Z</kbd>后，此时作业会进入`Stop`状态，终端就会被释放，后续追加命令可以更改作业的状态：

1. 输入`fg %<id>`，恢复指定作业的运行，再次独占终端，若不带序号，则优先恢复最后进入`Stop`状态的作业；
2. 输入`bg %<id>`，将指定作业放置于后台运行，不会独占终端，若不带序号，则优先恢复最后进入`Stop`状态的作业。

> [!tip]
>
> 需要注意的是，假设使用`bg`来将作业放置于后台运行，若这个作业存在输出，则可能会影响终端命令的输入，因此最好将输出定向到某一个日志文件中，不要直接在终端中回显作业的日志输出。

被暂停的作业序号可以通过命令`jobs`来查看。

## 短命名命令

类似于C/C++中的宏和using关键字，使用`alias`可以给某个特定的命令进行命令，例如：
~~~bash
alias ll="ls -lah"
ll
~~~

此时执行`ll`就等价执行了`ls -lah`命令，若不将`alias`加入`.bashrc`中，则该`alias`仅在该终端中生效。
