# 处理类型

​    随着程序复杂度提升，用到的数据类型和变量名会越来越复杂，这个时候再用复杂名字进行编程就没什么必要了。可以尝试通过一些方法处理类型来方便我们阅读程序或者编写程序。

## 类型别名

​    在C语言中我们接触过关键字`typedef`，能够给予指定数据类型另一个名字，具体的就不赘述了。

​    除了关键字`typedef`以外，C++11之后还可以使用 **别名声明（alias declaration）** 来定义类型的别名：
~~~c++
using SI = Sales_item;
~~~

> [!WARNING]
>
> 如果使用类型别名指代复合类型或者常量，有时候可能会产生意想不到的误解，例如：
> ~~~c++
> typedef char *pstring;
> const pstring cstr = 0; //cstr是指向char的指针常量
> ~~~
>
> 如果错误地将其理解为宏替换：
> ~~~c++
> const char* cstr = 0; //cstr是指向const char的指针
> ~~~
>
> 则会产生误解，第一段程序中的`cstr`是声明了一个指向`char`的指针常量，第二段程序中则是声明了一个指向`const char`的指针。

## auto类型

   C++11新增了一种类型 **auto类型** ，这种类型的是为了解决编写程序时某些变量的类型暂时无法被推断出来而存在的。对于被该关键字修饰的变量，编译器会替我们通过初始值分析变量所属的类型，因此， **auto类型的变量必须要有初始值** ：
~~~c++
auto item = val1+val2; //通过推断等式右边的表达式来确定item变量的数据类型
~~~

同时auto类型会 **忽略掉顶层const，保留底层const** 。例如：
~~~c++
int i = 0;
const int ci = i,&cr = ci;

auto a = ci; //a是一个整数int（ci的顶层const被忽略了）
auto b = cr; //b是一个整数int（cr是ci的引用，而ci本身是一个顶层const）
auto c = &i; //c是一个整型指针int*
auto d = &ci; //d是一个指向整数常量的指针const int*（对常量对象取地址是一种底层const）
~~~

> [!NOTE]
>
> 对常量对象取地址是一种底层const,会返回一个指向对应常量类型的指针数据类型。

如果需要保留顶层const，则需要用const修饰auto类型：
~~~c++
const auto a = ci;
~~~

此时a就是一个整数常量。

> [!WARNING]
>
> 如果要在同一条语句中定义多个变量，则 **所有等式的右边必须是同一种数据类型** ，否则会产生报错，例如：
> ~~~c++
> int i = 1025;
> const int ci = i;
> 
> auto k = ci, &l = i; //推导出int
> auto &m = ci,*p = &ci; //推导出int
> auto &n = i,*p2 = &ci;
> ~~~
>
> 其中第6行的语句是错误的，因为i的类型是`int`而ci的类型是`const int`，这就导致了编译器无法推导到底是`int`还是`const int`。

## decltype类型指示符

​    有时候我们必须要知道定义的变量类型，但又不想通过auto来修饰它，因为这样就必须初始化它，这个时候可以尝试使用 **decltype类型指示符**，它的作用是 **选择并返回操作数的数据类型** 。在此过程中编译器分析表达式并得到它的类型，但并不实际计算表达式，例如：
~~~c++
decltype(f()) sum = x; //sum的类型就是函数f()的返回类型
decltype(val1+val2) num = y; //num的类型就是表达式val1+val2的数据类型
~~~

假设decltype内的表达式是一个变量，则会返回变量的类型（包括顶层const和引用在内）：
~~~c++
const int ci = 0 , &cj = ci;

decltype(ci) x = 0; //const int
decltype(cj) y = x; //const int&
~~~

> [!WARNING]
>
> C++ 的 `decltype` 推导规则有一条核心准则：**如果表达式的结果是一个左值（lvalue），`decltype` 会推导为该类型的引用** 。例如：
> ~~~c++
> int i = 33,*p = &i, &r = i;
> decltype(r+0) b;//加法的结果为int，b为一个未初始化的int数据
> decltype(*p) c;//错误：c是int&，必须进行初始化
> ~~~
>
> 为了让第2行推导的结果是`int`而不是`int&`，我们利用表达式`r+0`使其返回类型变为`int`。
>
> 其中第三行是错误的，可能你会想表达式`*p`的数据类型不应该是`int`吗，为什么decltype的推断结果会是`int&`？
>
> 本质上`*p`的数据类型确实是`int`，但最后推断结果不一致是因为表达式 `*p` 是**解引用操作**。解引用指针会返回一个**左值**，即 `p` 所指向的那个内存实体（也就是变量 `i` 本身）。
>
> 左值是指 **能够对表达式进行取址操作`&`的表达式** ，例如`&i`；右值是指 **临时数据，无法对表达式进行取址操作`&`表达式**，例如`&(i+2)`。可以通过查看该数据是否在内存中长期存在来判断表达式是左值还是右值。
>
> 意味着如果decltype内的表达式会返回一个左值的话，那么推断的则会是一个引用。但如果只是传递一个单独的 **无括号** 变量标识符，则推断变量的类型，这是一个例外。如果加上一个括号，则会将单独的变量标识符变为一个表达式，此时就会推断出引用类型：
>
> ~~~c++
> int i = 42;
> decltype((i)) a = i; //int&
> ~~~
>
> 那么哪些操作会返回一个左值？如下所示：
>
> 1. **基础标识符**
>
>    只要单独写出一个变量名，它就是左值。例如：`i`、`p` 本身都是左值表达式。
>
> 2. **解引用与下标运算**
>    解引用 `\*`：`*p` 总是左值（指向的内存实体）。
>    下标 `[]`：`arr[0]` 本质是 `*(arr + 0)`，总是左值（数组中的特定元素）。
>
> 3. **数据成员访问操作（`.` 和 `->`）**
>
>    **`->`**（箭头）：无论左边是什么，`ptr->member` **总是左值**（因为它先解引用指针）。
>    `.`（点号）：取决于左边的对象。
>
>    - 如果左边是**左值**，则 `obj.member` 是**左值**。
>    - 如果左边是**右值**（临时对象），则 `obj.member` 是**右值**。
>    - *特例*：如果访问的是**数据成员**，且该成员是引用类型，或者访问的是**数组元素**，即使对象是右值，`obj.member` 也可能是左值（但这属于较深的细节）。
>
> 4. **赋值与复合赋值操作**
>    赋值 `=`：`i = 10` 这个表达式整体返回 `i` 本身，是**左值**（C++ 特有，允许 `(i = 10) = 20` 这种链式赋值）。
>    复合赋值：`+=`、`-=`、`*=`、`%=`、`<<=` 等，返回值都是左侧操作数的引用，因此都是**左值**。
>
> 5. **自增/自减（前缀版本）**
>    前缀 `++i` / `--i`：返回的是修改后的变量本身，是**左值**。
>    *注意*：**后缀 `i++`** 返回的是修改前的副本（临时量），那是**右值**。
>
> 6. **返回左值引用的函数调用**
>
>    如果函数的返回类型是 `T&`（左值引用），那么该函数调用表达式就是**左值**。
>
>    - 例如：`std::vector<int> v; v[0]` 返回 `int&`，所以 `v[0]` 是左值。
>    - 例如：`std::cout << "hi"` 返回 `std::ostream&`，所以整体是左值。
>
> 7. **显式类型转换（转换为左值引用）**
>    使用 `static_cast<int&>(x)` 或 `(int&)x`，强制转为引用类型，结果就是左值。
>
> 8. **字符串字面量**
>    常量字符数组 `"Hello"` 是存储在静态存储区的数组，它代表地址，因此是**左值**（注意：普通整数字面量 `42` 是右值）。
