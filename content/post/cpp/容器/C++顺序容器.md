# C++顺序容器

​    在之前的章节中我们已经接触过了其中两个顺序容器`vector` 、`string`，而所谓 **顺序容器** ，就是能为程序员提供 *控制元素存储和访问顺序* 的能力。下面是C++标准库中的顺序容器

|     容器类型      |                             说明                             |
| :---------------: | :----------------------------------------------------------: |
|    `vector<T>`    | 可变大小数组，，支持快速随机访问，在尾部之外的位置插入或者删除元素可能很慢 |
|    `deque<T>`     |   双端队列，支持快速随机访问。在头尾位置插入/删除速度很快    |
|     `list<T>`     | 双向链表，且支持双向顺序访问。在list中任何位置进行插入/删除速度都很快 |
| `forward_list<T>` | 单向链表，且只支持单项顺序访问，在链表任何位置进行插入/删除速度都很快 |
|   `array<T,n>`    | 固定大小（大小为n）数组，支持快速随机访问，不能添加或者删除元素 |
|     `string`      | 与`vector`相似的容器，专门用于处理字符串，随机访问速度快且在尾部添加/删除速度快 |

对于上述例如不能进行随机访问的`list`、`forward_list`这些类型，一般都是为了保证在其中任何位置插入/删除速度都很快而做出的取舍。

与之相对应的是，对于在某些特殊位置插入很慢的类型。例如`vector`、`string`等，这是由于这些类型一般都是连续存储的，在某些位置（例如中间）进行插入/删除操作会需要移动大量元素以保证连续存储，因此就需要耗费更多的时间。

## 容器操作

​    所有的容器都具有一系列通用的操作，主要分为 **类型别名、构造函数、赋值与swap、大小、添加/删除元素、获取迭代器** 这几个方面。

### 类型别名

如下表所示：
|     类型别名      |                        说明                        |
| :---------------: | :------------------------------------------------: |
|    `iterator`     |                   常规迭代器类型                   |
| `const_iterator`  |   迭代器常量，可以读取元素，但无法通过其修改元素   |
|    `size_type`    | 无符号整数类型，可以保存此种容器最大可能容器的大小 |
| `different_type`  |      带符号整数类型，保存两个迭代器之间的距离      |
|   `value_type`    |                      元素类型                      |
|    `reference`    |         元素的左值类型，等价`value_type&`          |
| `const_reference` |    元素的const左值类型，等价`const value_type&`    |

### 构造函数

如下表所示：

|       构造函数        |                             说明                             |
| :-------------------: | :----------------------------------------------------------: |
|        `C c;`         |                   默认构造函数，构造空容器                   |
|      `C c1(c2);`      |                        构造c2的拷贝c1                        |
|      `C c(b,e);`      | 构造c，将迭代器 b 和 e 指定的范围内的元素拷贝到c<br /> **array不支持** |
| `C c [=] {a,b,c...};` |                         列表初始化c                          |

对于顺序容器，其构造函数还可以接受大小参数：

|  构造函数  |                             说明                             |
| :--------: | :----------------------------------------------------------: |
|  `C c(n)`  | c包含n个元素，这些元素进行了值初始化。<br />该构造函数被explicit修饰。<br />`string`类型不适用。 |
| `C c(n,t)` |                     c包含n个值为t的元素                      |

### 赋值与swap

如下表所示：

|    赋值与swap     |                       说明                       |
| :---------------: | :----------------------------------------------: |
|     `c1 = c2`     |             将c1中元素替换为c2中元素             |
| `c1 = {a,b,c...}` | 将c1中元素替换为列表中元素<br /> **array不支持** |
|    `a.swap(b)`    |           交换a与b之间的元素，旧版规范           |
|    `swap(a,b)`    |                  同上，新版规范                  |

对于除了关联容器和`array`类型以外的容器，还可以进行赋值（assign）操作：

|      操作       |                             说明                             |
| :-------------: | :----------------------------------------------------------: |
| `c.assign(b,e)` | 将c中的元素替换为迭代器b和e所表示的范围内元素， **迭代器b和e不能指向c中的元素** |
|  `c.assign(i)`  |              将c中的元素替换为初始化列表i中元素              |
| `c.assign(n,t)` |                将c中元素替换为n个值为t的元素                 |

> [!WARNING]
>
> 赋值相关操作会导致指向左边容器内部的迭代器、引用、指针失效。
>
> swap操作只会将容器内容进行交换，不会导致指向容器内部的迭代器、引用、指针失效（string、array类型除外），但可能会导致原有的迭代器、引用、指针指向的元素发生变化。
>
> 同时需要注意，对两个array类型进行swap操作，由于会 **真正交换两者内容** ，因此所需要的时间不再是常数级别，而是与array中元素数目成正比。这也导致了原有array内部的迭代器、引用、指针指向的元素不会发生变化。

### 大小

如下表所示：
|      大小       |                             说明                             |
| :-------------: | :----------------------------------------------------------: |
|   `c.size()`    |                        c中元素的数目                         |
| `c.max_size()`  |                   c中可保存的最大元素数目                    |
|   `c.empty()`   |               判空c，空返回true，否则返回false               |
|  `c.resize(n)`  | 调整c的大小为n个元素。<br />若n小于原有c的大小，则舍弃多余元素<br />若n大于原有c的大小，则对新增的元素进行值初始化<br />不支持`array` |
| `c.resize(n,t)` | 调整c的大小为n个元素，任何新增的元素都被初始化为t<br />不支持`array` |

### 添加/删除元素

如下表所示：

|                添加/删除元素                |                  说明                  |
| :-----------------------------------------: | :------------------------------------: |
|  `c.push_back(t)`<br />`c.emplace_back(args)`  | 在c的尾部创建值为t或由args创建的一个元素，返回void |
| `c.push_front(t)`<br />`c.emplace_front(args)` | 在c的头部创建值为t或由args创建的一个元素，返回void |
| `c.insert(p,t)`<br />`c.emplace(p,args)` |             在迭代器p指向的元素之前创建值为t或者由args创建的一个元素，返回指向新添加元素的迭代器             |
|                 `c.insert(p,n,t)`                 |      在迭代器p指向的元素之前插入n个值为t的元素，返回指向新添加的第一个元素的迭代器，若n=0，则返回p      |
| `c.insert(p,b,e)` | 在迭代器p指向的元素之前插入由迭代器b和e指定的范围内的元素，b和e不能指向c中元素，返回指向新添加的第一个元素的迭代器，若范围为空，则返回p |
| `c.insert(p,i)` | 在迭代器p指向的元素之前插入一个由花括号包围的元素值列表i，返回指向新添加的第一个元素的迭代器，若列表为空，则返回p |
| `c.pop_back()` | 删除c中尾元素。若c为空，则函数行为未定义，返回void |
| `c.pop_front()` | 删除c中头元素。若c为空，则函数行为未定义，返回void |
| `c.erase(p)` | 删除迭代器p指定的元素，返回一个指向被删元素之后元素的迭代器。若p指向尾元素，则返回尾后迭代器，若p为尾后迭代器，则函数行为未定义 |
| `c.erase(b,e)` | 删除迭代器b和e指定范围内的元素，返回一个指向最后一个被删除元素之后元素的迭代器，若e本身为尾后迭代器，则函数返回尾后迭代器 |
| `c.clear()` | 删除c中所有元素，返回void |

需要注意下面的限制：

- `array`类型不支持上述操作
- `forward_list`类型有其自己的`insert`、`emplace`、`erase`成员函数版本，
- 且不支持`push_back`、`emplace_back`、`pop_back`
- `vector`和`string`不支持`push_front`、`emplace_front`、`pop_front`

> [!TIP]
>
> 了解`push`、`insert`和`emplace`之间的区别：
>
> ​    其中`emplace_back`,`emplace`,`emplace_front`分表代表`push_back`,`insert`,`push_front`。
>
> `emplace`的操作是直接在容器中构造元素，而与之相对应的是，`push`和`insert`则是先创建一个临时局部变量，并将其压入容器中。
>
> 因此对于`emplace`可以直接类似于构造函数那样使用，只需要传递构造对象所需要的args参数即可，但`push`和`insert`就不能这样，例如：
> ~~~C++
> #include<iostream>
> #include<vector>
> 
> using namespace std;
> 
> class Base_Data{
>     int data;
> public:
>     Base_Data(int dt):data(dt){}
>     int get_data();
> };
> 
> int Base_Data::get_data(){ return this->data; }
> 
> int main(){
>     vector<Base_Data> v;
>     v.emplace_back(10); //可以直接传递构造参数
>     v.push_back(Base_Data(12)); //不能直接传递构造参数，需要先创建临时对象
> 
>     for(Base_Data bd : v)
>         cout << bd.get_data() << " ";
>     return 0;
> }
> ~~~
>
> 运行结果如下：
> ~~~bash
> 10 12 
> ~~~

如下表所示：
|       获取迭代器        |                   说明                    |
| :---------------------: | :---------------------------------------: |
|  `c.begin()`,`c.end()`  | 返回指向c的首元素和尾元素之后位置的迭代器 |
| `c.cbegin()`,`c.cend()` |           返回`const_interator`           |

### 反向容器的额外成员

如下表所示：

|    反向容器的额外成员     |                   说明                    |
| :-----------------------: | :---------------------------------------: |
|    `reverse_iterator`     |          按逆序寻址元素的迭代器           |
| `const_reverse_iterator`  |         不能修改元素的逆序迭代器          |
|  `c.rbegin()`,`c.rend()`  | 返回指向c的尾元素和首元素之前位置的迭代器 |
| `c.crbegin()`,`c.crend()` |       返回`const_reverse_iterator`        |

> [!WARNING]
>
> `forward_list`不支持上述操作。除此之外，`forward_list`迭代器也不支持递减运算符。
>
> 这里可以思考一下为什么不行，可以从单向链表这个数据结构的特征入手。

关于反向迭代器，在后续涉及到 **泛型算法** 的部分进行详细说明。

### 访问元素

对于顺序容器，可以使用不同的访问方法访问容器内的元素：
|    操作     |                             说明                             |
| :---------: | :----------------------------------------------------------: |
| `c.back()`  | 返回c中尾元素的引用，若c为空，则函数行为未定义<br />不适用于`forward_list` |
| `c.front()` |        返回c中头元素的引用，若c为空，则函数行为未定义        |
|   `c[n]`    | 返回c中下标为n的元素的引用，n为无符号整数，若n超过c的size，则函数行为未定义<br />只适用于`string`、`vector`、`deque`、`array` |
|  `c.at(n)`  | 返回下表为n的元素引用，若下表越界，则抛出`out_of_range`异常<br />只适用于`string`、`vector`、`deque`、`array` |

### 管理容器容量

​    某些成员函数可以提前告诉容器我们准备存储的元素个数，或者让我们知道容器最大的容量是多少，如下表所示：
|        操作         |                             说明                             |
| :-----------------: | :----------------------------------------------------------: |
| `c.shrink_to_fit()` | 将`capacity()`减少为与`size()`相同大小<br />只适用于`vector`、`string`、`deque` |
|   `c.capacity()`    | 不重新分配内存的前提下，c可以保存多少元素<br />只适用于`vector`、`string` |
|   `c.reverse(n)`    | 分配至少能容纳n个元素的内存空间<br />只适用于`vector`、`string` |

> [!TIP]
>
> 只有当需要的内存空间超过当前容量时，reverse才会改变vector的容量。如果需求小于或者等于当前容量，则reverse什么都不做。
>
> 调用shrink_to_fit不一定保证退回多余的内存空间。

## 特殊的forward_list操作

​    关于为什么forward_list需要设置特殊的操作，可以了解一下单链表的概念和性质。下表是相关的特殊操作：
|                             操作                             |                             说明                             |
| :----------------------------------------------------------: | :----------------------------------------------------------: |
|         `c.before_begin()`<br />`c.cbefore_begin()`          | 返回指向链表首元素之前不存在的元素的迭代器。该迭代器不能解引用。<br />`cbefore_begin`返回一个`const_iterator`类型 |
| `c.insert_after(p,t)`<br />`c.insert_after(p,n,t)`<br />`c.insert_after(p,b,e)`<br />`c.insert_after(p,i)` | 在迭代器p之后插入元素。<br />`insert_after(p,t)`插入一个值为t的元素<br />`insert_after(p,n,t)`插入n个值为t的元素<br />`insert_after(p,b,e)`插入迭代器b和e指定范围的元素，不能指向容器c本身的元素<br />`insert_after(p,i)`插入由列表定义的元素序列。<br />若范围为空，则返回p；若p为尾后迭代器，则函数行为未定义 |
|                   `emplace_after(p,args)`                    | 使用args在p指定的位置之后创建一个元素。返回一个指向这个新元素的迭代器。若p为尾后迭代器，则函数行为未定义 |
|         `c.erase_after(p)`<br />`c.erase_after(b,e)`         | `erase_after(p)`删除迭代器p指向位置之后的元素<br />`erase_after(b,e)`删除迭代器b和e指定范围内的元素（不包含迭代器b和e之间的元素） |

其中的`before_begin()`获取的是前驱指针，需要配合`begin()`进行使用。

## 容器适配器

​    标准库中还有三个顺序容器适配器：`stack`、`queue`、`priority_queue`。适配器（adaptor）能够让某种事物的行为看起来像另一种事物一样。

​    而容器适配器接受一种已有的容器类型，使其行为看起来像一种不同的类型。下表列出了所有容器适配器支持的操作和类型：
|          操作、类型          |                            说明                            |
| :--------------------------: | :--------------------------------------------------------: |
|         `size_type`          |             足以保存当前类型最大对象的大小类型             |
|         `value_type`         |                          元素类型                          |
|        `contain_type`        |                  实现适配器的底层容器类型                  |
|            `A a;`            |                     创建一个空适配器a                      |
|          `A a(c);`           |               创建一个带有容器c拷贝的适配器a               |
|          关系运算符          |                   返回底层容器的比较结果                   |
|         `a.empty()`          |            判空适配器a，若空返回true，否则false            |
|          `a.size()`          |                     返回适配器a的大小                      |
| `swap(a,b)`<br />`a.swap(b)` | 交换a和b的内容，两者必须有相同类型，底层容器类型也必须相同 |

定义一个适配器有两种方式：

1. 像顺序容器那样定义一个适配器，例如：
   ~~~C++
   stack<int> stk(c); //将c中的元素拷贝到适配器stk中
   ~~~

2. 传递第二个参数来重载默认容器类型，例如：

   ~~~c++
   stack<string,vector<string>> stk(c); //将c中元素拷贝到适配器stk中，并重载stk的底层容器类型
   ~~~

> [!TIP]
>
> 每个适配器都默认有自己的默认容器类型。`stack`和`queue`是基于`deque`实现的；`priority_queue`是基于`vector`实现的。
>
> 如果要重载默认容器类型，则用于重载的容器必须 **拥有添加和删除元素、访问尾元素的能力** ，因此`array`、`forward_list`无法用于重载适配器的容器类型。同时每个适配器所拥有的不同操作也会导致部分容器无法用于重载。
>
> 总之，各适配器无法用于重载的容器类型如下：
>
> 1. `stack`：无法基于`array`、`forward_list`重载
> 2. `queue`：无法基于`vector`重载
> 3. `priority_queue`：无法基于`list`重载

### stack适配器

所支持的操作如下表所示：

|                 操作                  |                             说明                             |
| :-----------------------------------: | :----------------------------------------------------------: |
|               `s.pop()`               |                删除栈顶元素，但不返回该元素值                |
| `s.push(item)`<br />`s.emplace(args)` | 创建一个元素压入栈顶。<br />该元素可通过拷贝或者移动item得到，也可以通过args构造 |
|               `s.top()`               |                    返回栈顶元素，但不删除                    |

### queue适配器

包含`queue`和`priority_queue`两种队列，所支持的操作如下表所示：
|                 操作                  |                            说明                            |
| :-----------------------------------: | :--------------------------------------------------------: |
|               `q.pop()`               |   返回队列中首元素或优先队列中最高优先级的元素，但不删除   |
|              `q.front()`              |         返回首元素，但不删除<br />只适用于`queue`          |
|              `q.back()`               |         返回尾元素，但不删除<br />只适用于`queue`          |
|               `q.top()`               | 返回最高优先级元素，但不删除<br />只适用于`priority_queue` |
| `q.push(item)`<br />`q.emplace(args)` |       在队列末尾或者优先队列中的适当位置创建一个元素       |

容器是C++中非常重要的工具之一，熟悉容器的使用能大幅提高开发效率，当然容器在算法比赛中也有非常重要的作用，不需要自己再去手搓相关的数据结构，大幅减少编写代码的时间。后续我们还会接触到另外一类容器：关联容器，其相比顺序容器的区别是关联容器中的元素是按照关键字来保存和访问的，类似于python中的字典。
