# 函数重载

​    C++中允许针对同名函数进行重载，从而实现同名函数附带不同功能的需求，例如下面是一部分函数重载的例子：
~~~C++
int add(int a,int b);
int add(int a,int b,int c);
double add(double a,double b);

//下面是错误的函数重载
double add(int lval,int rval); //无法仅依赖返回类型来重载函数
int add(double lval,double rval); //同上
~~~

因此根据上述例子可以简单总结函数重载需要符合的条件：

> 如果形参列表元素数量一致，则必须存在一个元素数据类型不同；反之，则不允许形参列表元素数量一致
>
> 函数的返回类型是否相同不是函数重载的判断依据

> [!WARNING]
>
> 这里需要提醒一点的是，对于顶层const修饰的数据类型在重载函数中无法与没有顶层const的数据类型区分开，例如下述的函数重载是错误的：
> ~~~c++
> bool PrintInfo(message s);
> bool PrintInfo(const message s); //与上一个声明语句冲突
> 
> bool PrintInfo(message* s);
> bool PrintInfo(message* const s); //与上一个声明语句冲突
> ~~~
>
> 但相反，如果形参是某种类型的指针或者引用，则可以通过区分 **其指向的是常量对象还是非常量对象** 来实现函数重载，此时const是底层的：
> ~~~c++
> bool PrintInfo(message& s);
> bool PrintInfo(const message& s); //重载正确
> 
> bool PrintInfo(message* s);
> bool PrintInfo(const message* s); //重载正确
> ~~~
>
> 换句话就是函数重载 **能区分底层const的形参，但无法区分顶层const的形参** 。

## const_cast和重载

{{<postLinkCard path="/post/cpp/基础类型/C++中的类型显式转换" cover="auto" >}}

在上面的博客中曾介绍过`const_cast`，可以去除掉或加上底层const，该类型转换可以用在函数重载上，也是其最有用的地方。例如定义了一个函数如下所示：
~~~C++
const string &shorterString(const string &s1,const string &s2){
    return s1.size() <= s2.size()? s1:s2;
}
~~~

该函数接收两个字符串常量的引用并进行比较长度大小，返回长度更短的字符串的引用，当然我们也可以传递两个非常量字符串的引用进去，但是最终返回的依旧是一个字符串常量的引用，如果我们需要其返回一个非常量字符串的引用该怎么办？

这就可以配合`const_cast`和函数重载完成这个操作：
~~~c++
string &shorterString(string &s1,string &s2){
    auto &r = shorterString(const_cast<const string&>(s1),
                            const_cast<const string&>(s2)
                           )
    return const_cast<string&>(r);
}
~~~

> [!TIP]
>
> 关于非常量字符串引用的函数版本为什么不直接写成如下形式：
> ~~~c++
> string &shorterString(string &s1, string &s2) {
>     return s1.size() <= s2.size() ? s1 : s2;
> }
> ~~~
>
> 这是因为我们在进行编程时，都需要尽可能地去复用已经写好了的相同功能代码，这样如果需要更改函数中的代码，就可以直接在被复用代码中进行更改，不用同时更改多个地方。

---

函数重载是c++中比较重要的一个环节，使用得当可以减少调用函数时的工作量。在后面还会接触到重载的另一种类型：运算符重载，可以改变运算符原本的意思，但难度比函数重载要高很多。
