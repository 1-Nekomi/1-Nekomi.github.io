# 列表初始化

​    在C++11的新标准中，除了常规的初始化形式，还新增了利用列表进行初始化的方法，如下所示：
~~~c++
int a = 0; //C语言中的初始化形式
int a = {0}; //C++中的列表初始化形式之一
int a{0}; //C++中的列表初始化形式之一
int a(0); //C++中初始化对象的形式之一
~~~

在该新标准下，能够利用花括号对变量以及对象进行初始化，也可以进行赋值操作。

> [!WARNING]
>
> 需要注意的是，当用于内置类型的变量时，这种初始化形式有一个重要特点：如果我们 **使用列表初始化且存在丢失信息** 的风险，编译器会报错，例如：
> ~~~C++
> long double ld = 3.1415926536;
> int a{ld}, b = {ld}; // 错误：转换未执行，因为存在丢失信息的风险
> int c(ld), d = ld; // 正确：转换执行，且丢失了部分值
> ~~~
>
> 我们对上述程序进行编译，则会产生下列报错：
> ~~~bash
> main.cpp:2:7: warning: narrowing conversion of ‘ld’ from ‘long double’ to ‘int’ [-Wnarrowing]
>     2 | int a{ld}, b = {ld}; // 错误：转换未执行，因为存在丢失信息的风险
>       |       ^~
> main.cpp:2:17: warning: narrowing conversion of ‘ld’ from ‘long double’ to ‘int’ [-Wnarrowing]
>     2 | int a{ld}, b = {ld}; // 错误：转换未执行，因为存在丢失信息的风险
>       |                 ^~
> ~~~
>
> 可以看到编译器对采用列表形式的初始化都进行了警告，但并没有对`int c(ld)`发出警告，说明这种丢失了部分值的初始化形式是被允许的，实际上这种形式是直接初始化了一个int对象，效果上与初始化一个变量没有区别，但 **在某些类型上可能会有隐式转换或拷贝构造的差异** 。
>
> 除此之外，请注意区分下面两种形式的初始化：
> ~~~C++
> int num  = {0}; //利用列表初始化了一个变量
> int nums[] = {0}; //初始化了一个数组
> ~~~
>
